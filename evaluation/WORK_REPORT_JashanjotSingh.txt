A.1  AI-tRPC ROUTER — FRONTEND-FACING AI ENDPOINTS
     File: server/routers/ai.ts
────────────────────────────────────────────────────────────────────────────────

Worked on the tRPC router that exposes AI functionality to the frontend.
Contributed to the implementation of AI endpoints that are consumed by
frontend pages, ensuring they receive properly structured data for UI
rendering:

- smartSearch Endpoint: Integrated the AI-powered natural language search
  query parsing. This endpoint analyzes user search queries (like "golden
  trophy for cricket tournament under 500 rupees") and returns structured
  JSON with interpreted intent, detected category, material, budget tier,
  use case, size, and extracted keywords. The frontend Search page consumes
  this to display AI-understood search chips and augment search results.

- similarProducts Endpoint: Built the product recommendation logic that
  queries the database for products in the same category as the current
  product, ordered by popularity (viewCount). Returns structured data
  (name, slug, category, material, shortDesc, imageUrl, priceHint) for
  rendering recommendation cards on the Product Detail page. Implemented
  the Prisma database query with category-matching and the current-product
  exclusion filter.

- generateDescription Endpoint: Set up the AI product description
  generation endpoint that constructs a detailed prompt requesting a
  2-3 paragraph SEO-optimized product description. Integrated this with
  the admin products management page where admins can click "Generate
  with AI" to auto-fill product descriptions.

- dashboardInsights Endpoint: Implemented the analytics insights endpoint
  that sends enquiry statistics to the AI and receives actionable business
  insights for display on the admin dashboard. Handles the JSON-structured
  response parsing with a fallback for when the AI is unavailable.

- Input Validation: Set up all Zod input schemas for the AI router
  endpoints with proper constraints — chatInput (1-30 messages),
  generateDescriptionInput (name 1-200 chars, optional material/category),
  smartSearchInput (query 1-200 chars), similarProductsInput,
  dashboardInsightsInput (with nested object arrays).

A.2  MEILISEARCH / DATABASE SEARCH ENGINE
     File: server/meilisearch.ts
────────────────────────────────────────────────────────────────────────────────

Migrated the product search system from Meilisearch (external search
service) to PostgreSQL-based text search using Prisma ORM:

- Implemented word-based matching: Split search queries into individual
  words (minimum 2 characters) and constructed OR conditions across 5
  text fields (product name, material, short description, full
  description, category name) for broader, more accurate matching.

- Added category filtering support with categorySlug parameter.

- Implemented multi-field sorting: isFeatured descending (featured
  products first), viewCount descending (popular products first),
  name ascending (alphabetical tiebreaker).

- Added pagination with limit/offset parameters and estimatedTotalHits
  count for paginated product listings.

- Made the search performance-measurable by tracking and returning
  processingTimeMs.

- Maintained backward compatibility with no-op stubs for
  configureProductIndex() and indexProducts() that log informational
  messages instead of making external API calls.

- This change eliminated the need for a separate Meilisearch service,
  reducing infrastructure complexity and operational costs.
