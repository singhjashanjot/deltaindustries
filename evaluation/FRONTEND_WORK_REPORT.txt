1.1  ChatWidget.tsx — Root Orchestrator
──────────────────────────────────────────
The entry point component that manages the open/closed state of the
chatbot. Uses a simple `useState(false)` for the `isOpen` toggle.

- Renders two child components: ChatFAB (the floating action button) and
  ChatPanel (the slide-up chat panel).
- Passes `isOpen` state down to both children and an `onClose` callback
  to ChatPanel so it can dismiss itself.
- Acts as a clean separation layer — all the complexity lives in ChatPanel.
- Exported as default and mounted in App.tsx's PublicLayout after the
  `<Outlet />`, making the chatbot available on every public-facing
  page of the website.

1.2  ChatFAB.tsx — Floating Action Button
───────────────────────────────────────────
A circular floating button fixed at the bottom-right corner of the
viewport that opens/closes the chat panel.

Props:
  - onClick: () => void — toggles the chat panel visibility.
  - isOpen: boolean — determines which icon to show.

Styling:
  - fixed bottom-6 right-6 z-50
  - 56x56 pixels (w-14 h-14)
  - rounded-full shape
  - Background: #35020D (the brand's deep maroon)
  - Text color: #ffffe3 (cream/ivory)
  - shadow-lg for depth elevation

Animations (framer-motion):
  - whileHover: { scale: 1.05 } — grows slightly on hover for feedback.
  - whileTap: { scale: 0.95 } — presses down on click/tap.

Icon Toggle:
  - When isOpen is true: Shows an X (close) icon — two SVG lines

  - When isOpen is false: Shows a chat bubble icon — SVG path drawing
    a speech bubble shape (the standard chat icon).

Accessibility:

    when closed — this provides context for screen reader users.

1.3  ChatPanel.tsx — Main Chat Interface (269 lines)
───────────────────────────────────────────────────────
THE core chat component — a slide-up panel with full conversation
capability, auto-generated smart chips, and product card rendering.

State Management:
  - messages: Message[] — array of chat messages, initialized with a
    single WELCOME_MESSAGE from the assistant.
  - input: string — current textarea input value.
  - isLoading: boolean — tracks whether an AI response is being awaited.

Refs:
  - messagesEndRef: HTMLDivElement — for auto-scrolling to the latest
    message.
  - inputRef: HTMLTextAreaElement — for auto-focusing after send.

Message Interface:
  interface Message {
    id: string;
    role: "user" | "assistant";
    content: string;
    products?: ProductData[];    // product cards to render
    isStreaming?: boolean;       // for typewriter animation
  }

Welcome Message:
  A hardcoded initial assistant message: "Good day. I am Delta
  Assistant, representing Delta Industries — trophy and awards
  manufacturers since 1998 in Jalandhar. How may I assist you with
  your recognition needs?"
  - Uses a fixed id "welcome" so it can be filtered out when sending
    conversation history to the AI (the system prompt already contains
    this context).

Panel Appearance & Animation:
  - Fixed positioning: bottom-24 right-6
  - Width: calc(100vw - 3rem) capped at max-w-[440px]
  - Height: calc(100vh - 7rem) capped at max-h-[750px]
  - Background: #ffffe3 (cream)
  - Border: 1px solid #35020D at 15% opacity
  - Shape: rounded-sm (subtle square corners)
  - Shadow: shadow-2xl for prominent depth
  - Font: font-sans
  - Enter animation: slides up from opacity: 0, y: 20, scale: 0.95 to
    full opacity and natural position in 0.25s with a custom cubic
    bezier ease [0.16, 1, 0.3, 1].
  - Exit animation: reverses the enter animation.

Panel Header:
  - Left side: The Delta brand mark (Greek capital letter Delta "Δ"
    inside a bordered square box), "Delta Assistant" title (14px,
    semibold, tracking-wide), "Online" status indicator (10px,
    uppercase, muted).
  - Right side: Close button with an X SVG icon (16x16 viewBox with
    two diagonal lines).

Messages Area:
  - Flex-1 scrollable container (overflow-y-auto) with padding.
  - Each message rendered as a <ChatMessage> component.
  - Product cards attached to messages render below the text in a
    vertical list with spacing.
  - Loading indicator: Three small pulsing dots (w-1.5 h-1.5
    rounded-full bg-[#35020D]/30 animate-pulse) with staggered
    animation delays (0ms, 150ms, 300ms) — creates a ripple loading
    effect.

Smart Chips (Contextual Quick Replies):
  A sophisticated `generateChips()` function analyzes the last
  assistant message to generate up to 3 contextual suggestion buttons.

  Detection Logic (3 checks before generating chips):
    1. asksQuestion: Regex `/[?]/` — checks if the message ends with
       a question mark.
    2. offersOptions: Regex matching phrases like "would you like",
       "let me know", "shall i", "may i", "can i help", "how may i",
       "what would you", "which one", "interested in".
    3. isFinalAnswer: Regex matching definite closing phrases like
       "hope this helps", "that covers", "those are", "this is the",
       "thank you for", "feel free to reach", "contact us directly",
       "submitted successfully".

  Chip Suppression Rules:
    - If the AI gave a definitive answer AND didn't ask a question —
      NO chips shown (the conversation is considered complete).
    - If the AI didn't ask a question AND didn't offer options —
      NO chips shown (no follow-up needed).

  Keyword-to-Chip Mappings (13 categories):
    If the AI's message contains certain keywords, relevant chips are
    auto-generated:
    - "wood" or "wooden" → "Show me more wooden trophies"
    - "acrylic" → "What acrylic awards do you have"
    - "metal", "gold", "silver" → "Show metal cup options"
    - "crystal" → "Tell me about crystal trophies"
    - "plastic", "economy", "budget", "cheap", "affordable" →
      "Browse budget-friendly options"
    - "medal" → "What medals are available"
    - "shield", "plaque" → "Shields and plaques details"
    - "corporate", "gift", "executive" → "Corporate gift options"
    - "price", "pricing", "quote", "cost", "rupees", "rs" →
      "Get a price estimate"
    - "order", "ordering", "enquiry", "enquire", "buy", "purchase" →
      "Submit an enquiry"
    - "custom", "personalize", "engrav", "logo" →
      "How does customization work"
    - "manufacturing", "process", "facility", "made" →
      "Tell me about your facility"
    - "delivery", "shipping", "timeline" →
      "What is the delivery timeline"

  Fallback Chips:
    - If no keyword-matched chips generated but the AI asked a question:
      Adds "Tell me more".
    - If the AI offered options:
      Adds "Show me the options".
    - Maximum 3 chips returned (via `.slice(0, 3)`).

  Chip Rendering:
    - Displays in a horizontal scrollable row with thin scrollbar
      (`.chips-scroll` CSS class).
    - Each chip is a pill button: rounded-full, border, text-xs
      font-medium, whitespace-nowrap.
    - Hover effect: background fills to 5% opacity, border darkens to
      40% opacity, text color deepens.
    - Clicking a chip calls handleSend() with the chip text as the
      message — same as typing and pressing Enter.
    - Chips row only renders when NOT loading and chips array is
      non-empty (condition: !isLoading && chips.length > 0).

Input Area:
  - Textarea (rows=1) that auto-grows through browser default behavior.
  - Enter key sends (without Shift); Shift+Enter adds newline.
  - Disabled state during loading (greyed out, cursor-not-allowed).
  - Placeholder: "Type your message..."
  - Styling: bg-[#35020D]/5 (5% maroon background), rounded-sm,
    focus state changes background to 8% opacity.

Send Button:
  - 36x36px square, rounded-sm.
  - Background: #35020D, text: #ffffe3.
  - Disabled when input is empty or loading (opacity drops to 30%).
  - Icon: An arrow/Send SVG (line + polygon creating a paper plane
    shape), 14x14 viewBox, strokeWidth 2.5.

Send Handler (handleSend):
  Flow:
  1. Validates input is non-empty and not already loading.
  2. Creates a user message with id = Date.now().toString().
  3. Appends the user message to the messages array.
  4. Clears the input field.
  5. Sets isLoading = true.
  6. Creates a placeholder assistant message (id = Date.now()+1)
     with empty content and isStreaming = true — triggers the
     typewriter animation in ChatMessage.
  7. Filters conversation history — excludes the welcome message
     (id "welcome") and any streaming messages to avoid sending
     incomplete data to the API.
  8. Calls chatMutation.mutateAsync() with the filtered conversation.
  9. On success: Updates the placeholder assistant message with the
     AI's response content and any product cards, sets isStreaming
     to false.
  10. On error: Checks if the error message contains "Rate limit" or
      "429" — if so, shows a rate-limit warning message asking to
      wait a few seconds. Otherwise shows a generic error message
      with contact info.
  11. Finally: Sets isLoading to false and auto-focuses the input
      after 100ms.

Keyboard Handler (handleKeyDown):
  - On Enter without Shift: Prevents default (newline insertion),
    calls handleSend().

Auto-Scroll:
  - useEffect scrolls to messagesEndRef whenever messages change,
    using behavior: "smooth" for a pleasant scrolling experience.

Auto-Focus:
  - When the panel opens (isOpen transitions to true), the input
    field is focused after 300ms (timeout allows the open animation
    to start before focus shifts).

1.4  ChatMessage.tsx — Message Rendering with Markdown & Typewriter (78 lines)
─────────────────────────────────────────────────────────────────────────────────
Renders individual chat messages with markdown parsing and a typewriter
effect for streaming responses.

Props:
  - message: { id, role, content, isStreaming? }
  - isLast: boolean (used for loading indicator logic)

Markdown Parser (parseContent function):
  Converts AI response text to HTML with 4 transformations:
  1. **bold** → <strong>bold</strong>
  2. *italic* → <em>italic</em>
  3. Double newlines → <br/><br/> (paragraph breaks)
  4. Single newlines → <br/> (line breaks)

  Earlier versions (from commit 2) had a much more complex parser
  supporting inline code, headers, horizontal rules, lists, and
  tables. This was simplified in commit 6 to the 4 core
  transformations above because the AI's system prompt explicitly
  forbids markdown tables and headers, making those parsing rules
  unnecessary.

Typewriter Effect:
  - When message.isStreaming is true, the component uses a
    `displayedContent` state to gradually reveal text.
  - Mechanism: A useEffect with a setTimeout(10ms) timer that
    increments the displayed length by 3 characters at a time until
    the full content is reached.
  - The content prop gets updated when the AI response arrives,
    and the effect catches up to the new length.
  - A blinking cursor element (w-1.5 h-4 bg-[#35020D]/40 animate-pulse)
    appears at the end of the text during streaming.

Rendering:
  - User messages: Right-aligned (justify-end), dark maroon background
    (#35020D), cream text (#ffffe3) — creates a chat bubble effect.
  - Assistant messages: Left-aligned (justify-start), light background
    (#35020D/5), left border accent (border-l-2 border-[#35020D]/20).
  - User content is plain text with whitespace pre-wrap.
  - Assistant content uses dangerouslySetInnerHTML to render parsed
    markdown HTML.
  - Max width: 85% of the panel (max-w-[85%]).

3.1  Core Changes (Commit 9)
──────────────────────────────
The Navbar evolved from a simple visibility toggle (visible only when
scrolled past 250px on the home page) to a sophisticated direction-
aware show/hide system.

Navigation Links Array:
  const navLinks = [
    { label: "Our Range", path: "/products" },
    { label: "Manufacturing", path: "/custom-orders" },
    { label: "Who We Are", path: "/about" },
    { label: "Quality Focus", path: "/quality" },
    { label: "Reviews", path: "/testimonials" },
  ];

New Scroll Behavior Logic:
  State: isVisible (boolean) replaces the old scrolled (boolean).

  The scroll handler (handleScroll) implements three behaviors:
  1. Always show if the mobile menu is open (isOpen === true).
  2. Always show if scrollY < 50 (at the very top of the page).
  3. When scrolling down AND past 100px: HIDE the navbar.
  4. When scrolling up: SHOW the navbar.
  5. After scrolling stops (400ms debounce via setTimeout): SHOW
     the navbar — ensures nav is accessible when the user pauses.

  Performance:
  - Uses { passive: true } on the scroll event listener for better
    scroll performance (no preventDefault needed).
  - Proper cleanup: removes event listener and clears timeout in
    the useEffect return function.
  - Dependency array includes isOpen so the handler re-binds when
    the mobile menu toggles.

Navbar Animation (framer-motion AnimatePresence):
  - The entire <header> is wrapped in AnimatePresence.
  - When isVisible is false, the header slides up and fades out:
    exit: { y: -100, opacity: 0 }.
  - When isVisible is true, the header slides down and fades in:
    initial: { y: -100, opacity: 0 } → animate: { y: 0, opacity: 1 }.
  - Transition: duration 0.4s, ease [0.16, 1, 0.3, 1].

Desktop Navigation:
  - Hidden on mobile (hidden lg:flex).
  - Each nav link has a group class and an underline animation:
    a 1.5px line that expands from w-0 to w-full on hover with
    transition-all duration-300 ease-out.
  - Search icon link (Search from lucide-react) with hover background.
  - "Contact" CTA button: filled maroon rounded-full button with
    shadow-sm, ml-4 for spacing from nav links.

Mobile Navigation (AnimatePresence):
  - Full-screen overlay (height: "100vh") that slides down from
    the header.
  - Each nav link at text-2xl font-normal tracking-tight.
  - Search link with icon.
  - "Contact" button: full-width, maroon background, rounded-full,
    separated by a border-t divider.

Brand Mark:
  - Greek letter Delta "Δ" in a bordered square box (w-8 h-8).
  - "Delta" text next to it: font-semibold, tracking-wide, uppercase.
  - Both elements in a group: border darkens on hover.

5.2  AI Smart Search Integration
───────────────────────────────────
  State:
    - query: raw input text.
    - debouncedQuery: the query sent to the search API.
    - aiResult: AISearchResult | null — AI-parsed search dimensions.
    - isAiProcessing: boolean — loading state for AI analysis.

  AISearchResult Interface:
    {
      interpretedAs?: string;    // Human-readable interpretation
      category?: string | null;  // Matching category slug
      material?: string | null;  // Detected material
      budget?: string | null;    // budget/mid-range/premium
      useCase?: string | null;   // sports/academic/corporate/etc.
      size?: string | null;      // small/medium/large
      keywords?: string[];       // Extracted search terms
    }

  handleSearch Flow:
    1. If query has 3+ words (natural language detection), sends
       the query to trpc.ai.smartSearch.useMutation().
    2. While processing, shows "Understanding your request..." with
       a spinning Loader2 icon.
    3. On success: Sets aiResult, combines original query + extracted
       keywords for broader search: [query, keywords.join(" ")]
       .filter(Boolean).join(" ").
    4. On failure: Falls back to the original query without AI
       enhancement.
    5. Short queries (< 3 words): Bypass AI, search directly.

  removeAiFilter:
    - Clears aiResult and searches with the raw query text.

──────────────────────────────
  When aiResult exists (and not processing):

  Header:

17. PRODUCT IMAGE MAPPING UTILITY
    File: src/lib/product-images.ts (84 lines, NEW FILE)
────────────────────────────────────────────────────────────────────────────────

17.1  Purpose
───────────────
  Maps product database records to actual product photo files stored
  in public/IMAGES/. Without this utility, products would show
  placeholder icons instead of real photographs.

17.2  Image Catalogs
──────────────────────
  PC_IMAGES: 59 filenames for Plastic Cup products.
    ["PC-20.jpg", "PC-21.jpg", "PC-22.jpg", ... "PC-346.jpg"]

  WA_IMAGES: 48 filenames for Wooden Award products.
    ["WA-01 25MM.jpg", "WA-02 18MM.jpg", ... "WA-48 18MM.jpg"]

  Note: Filenames contain literal spaces (e.g., "WA-01 25MM.jpg"),
  which requires URL encoding in the browser.

17.3  getProductImage() Function
───────────────────────────────────
  Resolution Priority:
  1. If product.imageUrl already starts with "/IMAGES/" → use it
     directly (real image already stored in the database).
  2. Category-based matching:
     - "wooden-trophies" slug or slug containing "wooden" →
       WA_IMAGES[product.id % WA_IMAGES.length]
     - "plastic-trophy-series" slug or slug containing "plastic" →
       PC_IMAGES[product.id % PC_IMAGES.length]
     - "metal-cups-trophies" or "metal"/"cup" in slug →
       PC_IMAGES[(product.id + 10) % PC_IMAGES.length] (offset by 10
       to avoid same images as plastic category).
     - "custom-medals" or "medal" in slug →
       PC_IMAGES[(product.id + 20) % PC_IMAGES.length] (offset by 20).
  3. Returns product.imageUrl or empty string for unmatched categories
     (acrylic, crystal, shields, corporate, trophy bases).

17.4  getProductImageUrl() Function
──────────────────────────────────────
  Public-facing wrapper that handles URL encoding:
  - If the raw imageUrl already starts with "/IMAGES/", uses it.
  - Otherwise delegates to getProductImage().
  - URL encoding logic (critical fix in commit 6):
    · Only encodes if the path has literal spaces AND doesn't already
      have percent-encoded spaces (%20).
    · Encodes each path segment individually with encodeURIComponent.
    · This prevents double-encoding (e.g., turning "%20" into "%2520").
