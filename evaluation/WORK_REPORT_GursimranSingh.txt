Designed and built the complete AI infrastructure module from scratch — a
TypeScript HTTP client for the Groq API (groq.com), a cloud-hosted LLM
inference provider offering high-speed access to open-weight models on
custom LPU (Language Processing Unit) hardware.

TYPE SYSTEM DESIGN:
  Designed a clean, layered type hierarchy for AI communication:

  - ChatMessage: { role: "user" | "assistant", content: string }
    The minimal public-facing message type accepted from the frontend —
    deliberately simple to keep the client-server contract clean.

  - ConversationEntry: { role: string; content?: string; tool_calls?:
    unknown[]; tool_call_id?: string }
    A richer internal type for building the full conversation array sent
    to the Groq API. Supports system prompts, assistant tool calls, and
    tool result messages — covering the complete OpenAI-compatible
    conversation format.

  - GroqResponseMessage: { role: string; content: string | null;
    tool_calls?: Array<{ id: string; function: { name: string;
    arguments: string } }> }
    Maps the exact shape returned by Groq's /v1/chat/completions endpoint.
    The tool_calls array contains function call objects generated by the
    LLM when it autonomously decides to invoke a tool.

  - ChatResult: { content: string; toolCallsUsed: string[];
    products: ChatProductCard[] }
    The final structured return type — contains the assistant's text
    response, a list of tool names invoked (for transparency/debugging),
    and any product cards extracted from tool results for UI rendering.

MODEL SELECTION & CONFIGURATION:
  - Chose Groq as the LLM provider for its industry-leading inference
    speeds (powered by custom LPU hardware) and OpenAI-compatible API
    format that enables easy provider/model swapping.

  - Initially configured with "openai/gpt-oss-20b" model, then upgraded
    to "meta-llama/llama-4-scout-17b-16e-instruct" — Meta's Llama 4 Scout
    with 17 billion parameters and 16 experts in a Mixture-of-Experts
    architecture. This model was selected for its:
    * Strong instruction-following capabilities
    * Native function-calling (tool-use) support
    * Fast inference on Groq's LPU hardware
    * 30,000 tokens-per-minute rate limit

  - GROQ_BASE_URL: "https://api.groq.com/openai/v1" — the OpenAI-
    compatible endpoint that enables standard message/tool formats.

API KEY MANAGEMENT:
  - Implemented getApiKey() that reads GROQ_API_KEY from process.env with
    descriptive error handling — throws a clear error message if the key
    is missing rather than failing silently.

GROQCLIENT CLASS — FULL IMPLEMENTATION:
  Designed and implemented the central HTTP client class with three
  primary methods:

  chatCompletion() — Low-Level API Method:
    - Makes raw HTTP POST to {baseUrl}/chat/completions using the native
      fetch() API available in Deno.
    - Builds request body with: model name, messages array, temperature
      (default 0.7), max_tokens (default 1024), tool definitions array,
      and tool_choice: "auto".
    - The "auto" tool_choice lets the LLM autonomously decide whether to
      call a tool or produce text — no forced tool usage, the model
      intelligently decides based on the user's query.
    - Supports disabling tools via options.useTools = false (for plain
      text generation and JSON mode).
    - Supports response_format parameter (e.g., { type: "json_object" })
      for structured JSON output from the LLM.
    - Proper error handling: on non-2xx response, reads the response body
      and throws an Error with both HTTP status and response text for
      debugging.
    - Sets Content-Type: application/json and Authorization: Bearer {key}
      headers.

  chat() — Conversational AI Method with Tool-Calling Loop:
    - The PRIMARY chat method used by the AI router's chat endpoint.
    - Constructs a full conversation array starting with the SYSTEM_PROMPT
      (the Delta Assistant persona), followed by all user and assistant
      messages from the chat history.
    - IMPLEMENTS A SOPHISTICATED TOOL-CALLING LOOP (max 5 rounds):
      Round 1: Sends the user's message + system prompt to Groq.
      If the LLM responds with tool_calls:
        a. Pushes the assistant's response (with tool_calls) into the
           conversation history.
        b. Calls executeToolCalls() from tools.ts to run each tool
           against the database.
        c. Pushes each tool's result back into the conversation as a
           "tool" role message (with matching tool_call_id for LLM
           context correlation).
        d. Tracks executed tool names in toolCallsUsed[].
        e. Collects extracted product cards in allProducts[].
        f. Makes another chatCompletion() call — the LLM now processes
           the tool results and can either produce a final response or
           request more tools.
      The loop continues for up to 5 rounds to handle multi-step
      interactions (e.g., search products → get details →
      submit enquiry).
    - Falls back to a graceful apology: "I apologise, I was unable to
      process that. Could you rephrase?" if the LLM returns no content
      after all rounds.
    - Returns a ChatResult with the final text, all tools used, and all
      product cards extracted.

  generateCompletion() — Simple Text Generation:
    - A streamlined interface for one-shot text generation without chat
      history or tools.
    - Calls chatCompletion() with useTools: false, wrapping the prompt
      in a single user message (no system prompt).
    - Used for product description generation and other single-turn tasks.
    - Returns the message content string, defaulting to empty if null.

  generateJsonCompletion<T>() — Structured JSON Generation:
    - A specialized method for deterministic structured output.
    - Uses responseFormat: { type: "json_object" } to instruct Groq to
      produce valid JSON.
    - Lower default temperature (0.3) for more deterministic output —
      critical for machine-parseable results.
    - Generics-based design: the type parameter T provides both the
      expected return type and the fallback shape.
    - Wraps JSON.parse() in try-catch — if the LLM produces malformed
      JSON, returns the provided fallback instead of crashing.
    - Used for smart search analysis, dashboard insights, and any
      endpoint requiring structured data extraction from natural language.

SINGLETON PATTERN:
  - Implemented module-level lazy singleton via getGroqClient().
  - Ensures only one HTTP client instance exists per server process,
    avoiding redundant API key loading and enabling connection reuse
    across requests.

A.3  AI TOOL SYSTEM — FUNCTION-CALLING INFRASTRUCTURE
     File: server/ai/tools.ts  (391 lines, NEW FILE — ENTIRELY BUILT BY GURSIMRAN)
────────────────────────────────────────────────────────────────────────────────

Designed and built the complete function-calling (tool-use) system that
enables the Groq-powered LLM to interact with the application database
and perform real actions beyond text generation. This is the bridge
between AI reasoning and real-world data.

TOOL DEFINITION TYPES:
  - ToolDefinition: Follows the OpenAI function-calling specification:
    { type: "function", function: { name, description, parameters
    (JSON Schema with typed properties, descriptions, enumerated
    items, and required field arrays) } }
  - GroqToolCall: { id: string, function: { name: string,
    arguments: string (JSON-encoded) } }

TOOL REGISTRY — 5 TOOLS DEFINED:

  Tool 1: search_products
    Purpose: Search the Delta Industries product catalog.
    Description: "Search for products in the Delta Industries catalog
    by name, material, category, or keywords."
    Parameters designed:
      - query (string, REQUIRED): The search query.
      - category (string, optional): Filter by category slug for
        targeted results.
      - limit (number, optional): Max results, default 5, capped at 10
        to prevent overwhelming responses.
    Schema follows JSON Schema specification — enables Groq's LLM to
    understand exactly what arguments to pass.

  Tool 2: get_product_details
    Purpose: Fetch complete details for a specific product.
    Description carefully worded: "Pass the product code like WA-06
    or PC-20 (not the full name). Accepts codes (WA-06) or slugs
    (wooden-award-wa-06)." — this explicit instruction in the tool
    description helps the LLM pass the right identifier format.
    Parameters:
      - slug (string, REQUIRED): Product identifier.

  Tool 3: get_categories
    Purpose: List all available product categories.
    Parameters: Empty properties object (no arguments needed).

  Tool 4: get_featured_products
    Purpose: Get featured/popular products for recommendations.
    Parameters: Empty properties object.

  Tool 5: submit_enquiry
    Purpose: Persist a customer enquiry to the database.
    Parameters designed with Indian business context:
      - customerName (string, REQUIRED): Full name.
      - email (string, REQUIRED): Email address.
      - phone (string, REQUIRED): Indian mobile number (10 digits).
      - organization (string, optional): Organization/school/company.
      - message (string, REQUIRED): Summary of requirements.
      - quantity (number, optional): Approximate quantity.
      - productId (number, optional): Database product ID for
        referencing a specific product.

TOOL EXECUTOR — executeTool() FUNCTION:
  Built a central dispatcher function with switch-case routing:

  search_products implementation:
    - Normalizes query to lowercase.
    - Enforces max 10 results limit.
    - Constructs Prisma OR query across 4 fields: product name,
      material, short description, and category name — all with
      case-insensitive "contains" matching.
    - Includes related category data and up to 3 sizes per product.
    - Returns structured JSON with found flag, count, and product
      array — each product includes id, name, slug, category info,
      material, short description, image URL, customization flag,
      and size details with price ranges (formatted as "Rs X-Y").

  get_product_details implementation — WITH FUZZY MATCHING:
    - Primary: Exact slug match via Prisma findUnique.
    - FUZZY FALLBACK (critical feature): If exact match fails:
      * Converts slug to searchable terms (replacing hyphens with
        spaces).
      * Searches for up to 3 products where name or slug contains
        the search term.
      * If exactly 1 match found → returns that product.
      * If multiple matches found → returns a "multiple: true" response
        with all candidates for the AI to disambiguate.
      * If no matches → returns helpful error: "No product matching
        'X' was found. Try using the product code like WA-06 or PC-20."
    - Returns deep product data: all sizes with prices, MOQ, stock
      status; all associated images ordered by sortOrder.

  get_categories implementation:
    - Queries active categories ordered by sortOrder.
    - Returns id, name, slug, and description for each.

  get_featured_products implementation:
    - Queries up to 6 products where isActive AND isFeatured.
    - Ordered by viewCount descending (most popular first).
    - Includes cheapest size for a "From Rs X" price hint.

  submit_enquiry implementation:
    - Creates an Enquiry database record using Prisma.
    - Handles optional fields (organization, quantity, productId)
      by converting undefined to null for database compatibility.
    - Returns success confirmation with enquiry ID and a message:
      "Delta Industries will contact you within 24 hours."

PRODUCT DATA EXTRACTION — extractProductsFromToolResult():
  - Defines ChatProductCard interface: { id, name, slug, category,
    material, shortDesc, imageUrl, priceHint }.
  - Parses JSON tool results to extract product data for UI rendering.
  - Handles three result formats:
    * Array of products (from search, featured).
    * Single product object (from get_product_details).
    * Falls through returning empty array for non-product tools.
  - Smart price hint extraction: checks for direct priceHint field
    first, then falls back to first size's priceRange.

TOOL CALL EXECUTION LOOP — executeToolCalls():
  - Iterates over each GroqToolCall from the LLM's response.
  - For each tool call:
    1. Parses the function.arguments JSON string with a try-catch
       (graceful degradation to empty args on parse failure).
    2. Calls executeTool() with the tool name and parsed arguments.
    3. Records the tool name in the executed[] tracking array.
    4. Extracts any product cards from the result.
    5. Pushes a "tool" role message back into the conversation via
       the pushToConversation callback — includes the tool_call_id
       for the LLM to correlate results with calls.
  - Returns { executed: string[], products: ChatProductCard[] } —
    both the transparency info (which tools were used) and the
    renderable product data.

B.1  AI ROUTER — 5 AI-POWERED BACKEND ENDPOINTS
     File: server/routers/ai.ts  (184 lines, NEW FILE — ENTIRELY BUILT BY GURSIMRAN)
────────────────────────────────────────────────────────────────────────────────

Designed and implemented the tRPC router that exposes all AI functionality
as type-safe API endpoints:

INPUT VALIDATION (Zod Schemas):
  - chatMessageSchema: Strict role enum ("user" | "assistant") with
    string content.
  - chatInput: Array of messages, minimum 1, maximum 30 — prevents
    excessively large payloads that would consume API rate limits.
  - generateDescriptionInput: Name (1-200 chars), optional material
    and category (each max 100 chars).
  - smartSearchInput: Query string (1-200 chars).
  - similarProductsInput: Product slug (min 1 char).
  - dashboardInsightsInput: Total and new enquiry counts, recent
    product views array, recent enquiry messages array.

ENDPOINT: ai.chat
  Purpose: The main conversational AI endpoint powering the chatbot.
  Implementation:
    - Gets the GroqClient singleton.
    - Calls groq.chat() with the user's messages array.
    - Returns: content (assistant's final text), toolCallsUsed
      (which tools were invoked), products (ChatProductCard array
      for UI rendering).
  This is the endpoint behind every message sent in the chat widget.

ENDPOINT: ai.generateDescription
  Purpose: Generate SEO-optimized product descriptions for admin use.
  Implementation:
    - Constructs a detailed prompt specifying:
      * Professional, SEO-optimized, 2-3 paragraphs
      * 150-250 words total
      * Highlight craftsmanship and material quality
      * Mention suitable use cases (events, ceremonies, occasions)
      * Describe visual appeal and finish
      * Note customization options
      * Formal tone, no emojis
      * Write only the description text
    - Calls groq.generateCompletion() with temperature 0.8 (creative
      but controlled) and maxTokens 512.
    - Returns { description: string }.

ENDPOINT: ai.smartSearch
  Purpose: AI-powered natural language search query understanding.
  Implementation:
    - Constructs a detailed analysis prompt with the full category
      list and instructions to classify the query into structured
      JSON dimensions:
      * interpretedAs: Human-readable interpretation
      * category: Matching slug from 9 predefined categories or null
      * material: wood/metal/acrylic/crystal/plastic/brass/marble/null
      * budget: budget/mid-range/premium or null
      * useCase: sports/academic/corporate/school/wedding/government
      * size: small/medium/large or null
      * keywords: Extracted search terms array
    - Uses generateJsonCompletion<SmartSearchResult>() with a fallback
      that passes the original query through unchanged.
    - The generic type parameter provides both the return type and
      defines the fallback shape — elegant type-safe design.

ENDPOINT: ai.similarProducts
  Purpose: AI-powered product recommendations on detail pages.
  Implementation:
    - Looks up the source product by slug to identify its category.
    - Finds up to 4 products in the SAME category (excluding current).
    - Orders by viewCount descending (popularity-based).
    - Returns source product info + recommendations array with full
      product data for rendering recommendation cards.
    - Returns empty recommendations if source product not found.

ENDPOINT: ai.dashboardInsights
  Purpose: AI-generated business intelligence for the admin dashboard.
  Implementation:
    - Constructs prompt with analytics data: total/new enquiry counts,
      recent product views, recent enquiry messages.
    - Instructs the AI to analyze and provide 3-4 actionable business
      insights plus a one-sentence summary.
    - Returns structured JSON with insights array and summary string.
    - Fallback gracefully handles AI unavailability.

ROUTER REGISTRATION:
  Registered the aiRouter in server/routers/index.ts under the "ai"
  namespace, making all 5 endpoints available at trpc.ai.* — this
  single integration point connects the AI system to the rest of
  the application.

ChatPanel.tsx — Main Chat Interface (269 lines):
  The most complex component in the widget system, implementing the
  complete chat experience:

  State Management:
    - messages: Message[] initialized with a hardcoded WELCOME_MESSAGE.
    - input: string for the textarea.
    - isLoading: boolean to prevent double-sends.

  SMART CHIP GENERATION SYSTEM (generateChips function):
    Built a sophisticated contextual suggestion engine:

    Detection Logic (3-stage check):
      1. asksQuestion: Regex detecting "?" in the AI's message.
      2. offersOptions: Regex matching phrases like "would you like",
         "let me know", "shall i", "may i", "can i help", "how may i",
         "what would you", "which one", "interested in".
      3. isFinalAnswer: Regex matching closure phrases like "hope this
         helps", "that covers", "submitted successfully", "contact us
         directly", "feel free to reach".

    Chip Suppression Rules:
      - If definitive answer AND no question → NO chips (conversation
        is complete).
      - If no question AND no options offered → NO chips (nothing to
        follow up on).

    Keyword-to-Chip Mapping (13 categories):
      Built a keyword detection system that generates contextual
      suggestion chips:
      - wood/wooden → "Show me more wooden trophies"
      - acrylic → "What acrylic awards do you have"
      - metal/gold/silver → "Show metal cup options"
      - crystal → "Tell me about crystal trophies"
      - plastic/economy/budget/cheap/affordable → "Browse budget-
        friendly options"
      - medal → "What medals are available"
      - shield/plaque → "Shields and plaques details"
      - corporate/gift/executive → "Corporate gift options"
      - price/pricing/quote/cost/rupees/rs → "Get a price estimate"
      - order/ordering/enquiry/enquire/buy/purchase → "Submit an
        enquiry"
      - custom/personalize/engrav/logo → "How does customization work"
      - manufacturing/process/facility/made → "Tell me about your
        facility"
      - delivery/shipping/timeline → "What is the delivery timeline"

    Fallback generation:
      - If AI asked a question but no keyword matched: "Tell me more"
      - If AI offered options but no keyword matched: "Show me the
        options"
      - Capped at 3 chips maximum (slice(0, 3)).

  Send Handler (handleSend):
    - Filters out welcome message and streaming messages from history.
    - Creates optimistic assistant placeholder with isStreaming: true
      for the typewriter animation.
    - Calls trpc.ai.chat.mutateAsync() to get AI response.
    - Error handling: Detects rate limit errors (429/rate limit in
      message) and shows a specific "high volume" message vs. a
      generic "unable to respond" fallback with contact info.
    - Auto-focuses input after send (100ms delay).

  Panel Design:
    - Slide-up animation via framer-motion AnimatePresence:
      initial: { opacity: 0, y: 20, scale: 0.95 }, 250ms duration,
      custom easing [0.16, 1, 0.3, 1].
    - Fixed positioning, responsive sizing (max-w-[440px],
      max-h-[750px]).
    - Cream background (#ffffe3), dark border, shadow-2xl.
    - Header with Delta brand mark, "Online" status, close button.
    - Loading indicator: 3 pulsing dots with staggered delays.
    - Auto-scroll to latest message on content change.

ChatMessage.tsx — Markdown Rendering & Typewriter Effect:
  Markdown Parser (parseContent):
    - Converts **bold** → <strong>, *italic* → <em>, double newlines

- getProductImage() function with category-based routing:

  * Only encodes spaces in filenames (e.g., "WA-01 25MM.jpg") when

  * Encodes path segments individually to prevent double-encoding
    bugs (e.g., preventing "%20" from becoming "%2520").
  * This fix was critical for the 48 WA images whose filenames
    contain literal spaces with dimension information.
